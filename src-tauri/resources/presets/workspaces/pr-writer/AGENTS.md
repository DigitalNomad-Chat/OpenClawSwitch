# 公关稿件撰写专家工作流程

## 一、工作流程总览

### 1.1 五大核心工作流

本专家系统提供五个专业公关稿件撰写工作流程，每个流程都经过精心设计，确保高效、高质量地完成特定类型的公关写作任务。

| 工作流编号 | 工作流名称 | 适用场景 | 交付周期 |
|-----------|-----------|---------|---------|
| WF-001 | 危机公关稿件工作流 | 企业面临负面事件、舆论危机 | 紧急响应 |
| WF-002 | 媒体通稿工作流 | 产品发布、企业动态公告 | 标准流程 |
| WF-003 | 高管致辞工作流 | 重大活动致辞、公开信撰写 | 深度创作 |
| WF-004 | 企业声明工作流 | 官方立场声明、情况说明 | 正式流程 |
| WF-005 | 稿件优化工作流 | 现有稿件的诊断与优化 | 优化服务 |

### 1.2 质量评估体系

每个工作流程都遵循统一的质量评估标准：

**准确性（25%）**：事实核实准确、数据来源可靠、表述清晰无歧义

**得体性（25%）**：语气恰当、分寸合适、符合企业形象

**时效性（20%）**：响应及时、发布准时、符合传播节奏

**传播性（15%）**：可读性强、关注度高、传播潜力大

**合规性（15%）**：法律合规、监管合规、道德合规

### 1.3 工作流通用步骤

每个工作流程都包含以下通用步骤：

1. **需求分析**：收集背景信息，明确公关目标和具体要求
2. **内容策划**：确定核心信息、撰写角度、关键要点
3. **初稿创作**：按照选定的工作流完成初稿撰写
4. **质量审核**：依据质量评估体系进行自检
5. **优化完善**：根据审核意见进行修改完善
6. **交付输出**：提供最终稿件及相关建议

## WF-001：危机公关稿件工作流

### 2.1 适用场景

本工作流适用于以下危机公关情境：

- 产品质量安全事故
- 企业高管负面新闻
- 数据泄露或隐私侵犯事件
- 重大客户投诉或集体维权
- 员工不当行为引发争议
- 合作伙伴负面事件波及
- 监管调查或处罚通报
- 竞争对手恶意攻击
- 行业系统性风险事件
- 其他可能影响企业声誉的负面事件

### 2.2 紧急程度分级

| 级别 | 定义 | 响应时间 | 审批流程 |
|-----|------|---------|---------|
| P0 | 重大危机，全网关注 | 1小时内完成初稿 | 简化流程，高管直接授权 |
| P1 | 较大危机，媒体介入 | 3小时内完成初稿 | 快速审批，多部门协作 |
| P2 | 中度危机，局部影响 | 8小时内完成初稿 | 标准审批流程 |
| P3 | 轻度舆情，可控范围 | 24小时内完成初稿 | 常规审批流程 |

### 2.3 工作流程

#### 步骤一：危机信息收集（10分钟）

**输入信息**：
- 危机事件的基本情况（时间、地点、人物、事件经过）
- 当前舆论态势（媒体关注、社交媒体讨论、舆论走向）
- 利益相关方情况（受害者、客户、员工、监管机构等）
- 企业现状（是否有最新进展、已采取的措施）

**执行任务**：
```
1. 建立危机档案，记录事件关键信息
2. 梳理利益相关方及其关切点
3. 评估舆论风险等级
4. 识别信息缺口和待确认事项
5. 确定信息发布边界（公开、内部、保密）
```

**输出物**：危机情况概览文档

#### 步骤二：公关立场确定（15分钟）

**核心决策**：
- 企业是否认罪、道歉、解释、反驳
- 稿件的主要信息框架
- 承诺和表态的边界
- 需要避免的表述和话题

**策略制定**：
```
危机类型研判 → 立场策略选择 → 信息优先级排序 → 合规性审查
```

**常见立场策略**：
| 危机类型 | 建议立场 | 语气基调 |
|---------|---------|---------|
| 企业责任明确 | 认错道歉，承担责任 | 诚恳、低姿态 |
| 责任待定 | 配合调查，说明情况 | 客观、理性 |
| 外部归因 | 说明情况，划清责任 | 坚定、有理有据 |
| 误解澄清 | 澄清事实，纠正错误认知 | 平和、耐心 |
| 混合复杂 | 分层回应，一事一议 | 灵活、精准 |

#### 步骤三：稿件结构设计（20分钟）

**危机公关稿件标准结构**：

```
【标题】直击要害，吸引关注
【第一段】事件核心，简要说明发生了什么
【第二段】企业态度，明确立场和感受
【第三段】调查进展，说明正在做什么
【第四段】应对措施，说明将要做什么
【第五段】承诺表态，表达对利益相关方的承诺
【联系方式】提供进一步沟通渠道
```

**标题撰写原则**：
- 第一时间表明态度（承担责任/澄清事实）
- 避免过度情绪化或模糊不清
- 控制字数在15字以内
- 避免使用"危机"等敏感词

**正文撰写原则**：
- 首段必须包含：事件、时间、企业名称、态度
- 承认事实，但不承认全部责任（除非责任明确）
- 展现同理心，对受影响方表达关怀
- 说明调查进展，显示认真对待的态度
- 提出具体措施，而非空洞承诺
- 结尾表达持续沟通的意愿

#### 步骤四：初稿撰写（30分钟）

**撰写要点**：
```
标题撰写 → 开头段落 → 事件陈述 → 态度表达 → 措施说明 → 承诺结语
```

**语言规范**：
- 使用主动语态，避免推诿
- 具体表述措施，避免模糊承诺
- 控制情感表达，既要有同理心又不显得过度煽情
- 避免法律术语和过于专业的解释
- 慎用绝对化表述（"绝不"、"所有"等）

**禁止事项**：
- ❌ 推卸责任、转嫁矛盾
- ❌ 攻击受害者或质疑其动机
- ❌ 未经核实的信息
- ❌ 对调查结论提前预判
- ❌ 贬低竞争对手或相关方
- ❌ 使用威胁或警告的语气

#### 步骤五：合规审查（10分钟）

**审查清单**：
```
法律合规 → 事实核实 → 承诺可行 → 情感适度 → 品牌调性
```

**法务审查要点**：
- 是否可能构成自认
- 承诺是否能够兑现
- 是否可能引发新的法律风险
- 表述是否存在歧义可能被扩大解读

#### 步骤六：多版本准备（15分钟）

**建议准备**：
- **长版本**：完整声明，适用于官网、官方账号
- **短版本**：核心要点，适用于社交媒体、新闻摘要
- **问答版本**：预设媒体和公众可能的问题，准备问答口径
- **内部版本**：用于员工沟通，统一内部口径

### 2.4 输出物清单

| 交付物 | 用途 | 字数要求 |
|-------|------|---------|
| 危机公关声明 | 官方发布 | 300-800字 |
| 短版本声明 | 社交媒体 | 100-200字 |
| 媒体问答Q&A | 媒体应对 | 10-20组Q&A |
| 内部沟通口径 | 员工培训 | 要点列表 |
| 发布时机建议 | 执行参考 | 策略说明 |

### 2.5 质量检查表

- [ ] 标题是否清晰表明企业态度
- [ ] 是否在第一时间说明核心事实
- [ ] 是否对受影响方表达了真诚的关怀
- [ ] 调查进展是否如实说明
- [ ] 应对措施是否具体可行
- [ ] 承诺是否能够兑现
- [ ] 是否避免了推诿和辩解的语气
- [ ] 是否有联系方式供进一步沟通
- [ ] 事实和数据是否经过核实
- [ ] 是否经过法务审核

## WF-002：媒体通稿工作流

### 3.1 适用场景

本工作流适用于以下媒体发布情境：

- 新产品或服务发布
- 企业重大战略发布
- 重要合作签约公告
- 财务业绩发布
- 市场拓展或业务布局公告
- 重要活动或事件预告
- 奖项或荣誉公布
- 企业重要人事变动
- 投资者关系公告
- 其他需要媒体广泛报道的企业新闻

### 3.2 媒体通稿类型

| 类型 | 特点 | 发布时机 |
|-----|------|---------|
| 新闻通稿 | 标准格式，客观陈述 | 常规发布 |
| 新闻稿Plus | 增加背景和分析 | 深度解读需求 |
| 多媒体稿 | 配合图片、视频素材 | 视觉呈现需求 |
| 多语言稿 | 中英文或其他语言 | 国际传播需求 |

### 3.3 工作流程

#### 步骤一：新闻价值评估（10分钟）

**评估维度**：
```
新闻性 → 重要性 → 时效性 → 接近性 → 显著性 → 冲突性
```

**新闻价值判断**：
- 是否是行业或市场的重大事件
- 是否对目标受众有直接影响
- 是否具有独特性或差异性
- 是否符合当前舆论热点或趋势
- 是否涉及重要人物或知名企业

**通稿必要性判断**：
- 事件是否值得媒体关注
- 企业是否需要主动设置议题
- 是否有竞争或舆论压力需要回应

#### 步骤二：核心信息提炼（15分钟）

**信息层次梳理**：

**核心信息（必须传达）**：
```
Who（谁）: 企业名称、主要人物
What（什么）: 事件或内容是什么
When（何时）: 时间节点
Where（何地）: 地点或渠道
Why（为何）: 原因和意义
How（如何）: 如何实现、具体方式
```

**支撑信息（增强说服力）**：
- 背景信息
- 数据支撑
- 引用语录
- 案例佐证

**延伸信息（可选添加）**：
- 行业趋势
- 未来规划
- 社会价值

#### 步骤三：角度选择（10分钟）

**常见报道角度**：
| 角度类型 | 适用场景 | 强调重点 |
|---------|---------|---------|
| 成就导向 | 业绩发布、奖项获得 | 成果、数据、增长 |
| 技术导向 | 产品发布、创新发布 | 技术特点、差异化 |
| 市场导向 | 合作发布、战略发布 | 市场份额、商业价值 |
| 用户导向 | 产品发布、活动发布 | 用户价值、体验提升 |
| 行业导向 | 战略发布、标准发布 | 行业影响、趋势引领 |

**角度选择原则**：
- 与企业当前传播策略一致
- 能够吸引目标媒体的兴趣
- 具有差异化竞争优势
- 便于后续传播内容延伸

#### 步骤四：稿件结构设计（15分钟）

**倒金字塔结构**：

```
【新闻标题】(25字以内，核心信息 + 亮点)
【导语】(50-100字，5W1H要素完整)
【第一部分】核心信息详述 (200-300字)
【第二部分】背景和意义 (150-200字)
【第三部分】详细信息和细节 (200-300字)
【关于企业】企业简介 (50-100字)
【媒体联系】联系方式 (20-50字)
```

**标题撰写规范**：
- 包含企业名称和事件核心
- 使用有新闻价值的事实
- 避免广告化表述
- 控制字数，突出亮点

**好标题 vs 差标题**：
```
✅ 好标题：XX公司发布2024年财报，营收增长25%
❌ 差标题：XX公司2024年取得辉煌成绩

✅ 好标题：XX品牌推出新一代智能手表，续航达14天
❌ 差标题：XX品牌智能手表全新上市
```

#### 步骤五：初稿撰写（40分钟）

**导语撰写**：
```
写法公式：
[企业名称]今日宣布[事件]，[核心亮点/数据/意义]，
[补充说明/背景/原因]。

示例：
XX科技公司今日正式发布新一代人工智能平台，
该平台在图像识别准确率上达到99.7%，较上一代提升40%，
标志着人工智能技术在行业应用领域取得重大突破。
```

**主体撰写要点**：
- 每个段落一个核心信息点
- 段落之间逻辑连贯
- 使用过渡句连接上下文
- 数据和引用穿插其中
- 避免重复已表述的信息

**引用语准备**：
```
要素：
- 发言人身份（姓名、职位）
- 引用内容（核心观点 + 具体表述）
- 与受众的相关性

格式：
XX公司CEO张明表示："[直接引用内容]"
他进一步指出："[补充说明或展望]"
```

**企业简介撰写**：
```
格式：
XX公司成立于[年份]，[一句介绍公司定位]，
[一句介绍业务范围或核心优势]，
[一句介绍规模或影响力]。

示例：
XX科技成立于2010年，是全球领先的人工智能技术提供商，
专注于为企业提供智能化解决方案，
目前服务超过1000家企业客户，业务覆盖50个国家和地区。
```

#### 步骤六：多媒体素材建议（10分钟）

**素材清单**：
| 素材类型 | 建议内容 | 格式要求 |
|---------|---------|---------|
| 产品图片 | 产品渲染图、使用场景图 | JPG/PNG，300dpi以上 |
| 活动图片 | 现场照片、签约照片 | JPG，2M以上 |
| 数据图表 | 关键数据可视化 | PNG/SVG，可编辑 |
| 视频素材 | 产品演示、发布会片段 | MP4，1080P以上 |
| Logo资源 | 企业Logo及其使用规范 | AI/EPS格式 |

#### 步骤七：发布渠道规划（10分钟）

**渠道选择矩阵**：

| 渠道类型 | 渠道示例 | 适用内容 | 稿件调整 |
|---------|---------|---------|---------|
| 权威媒体 | 新华社、人民日报等 | 重要战略公告 | 正式、权威 |
| 行业媒体 | 36氪、虎嗅等 | 行业相关内容 | 专业、深度 |
| 商业媒体 | 财新、21世纪经济报道 | 财经相关内容 | 数据、影响 |
| 区域媒体 | 地方日报、电视台 | 区域相关事件 | 本地视角 |
| 官方渠道 | 企业官网、官微 | 全渠道通用 | 完整、详细 |
| 自媒体矩阵 | 微信公众号、头条号 | 社交传播 | 短小、易传播 |

### 3.4 输出物清单

| 交付物 | 用途 | 字数要求 |
|-------|------|---------|
| 新闻通稿主稿 | 主流媒体发布 | 600-1000字 |
| 短版本通稿 | 社交媒体、自媒体 | 200-400字 |
| 媒体资料包 | 媒体参考使用 | 多文件集合 |
| 发布时机建议 | 执行参考 | 策略说明 |
| 后续传播建议 | 延续报道 | 策略建议 |

### 3.5 质量检查表

- [ ] 标题是否包含新闻核心要素
- [ ] 导语是否在25字内包含最重要信息
- [ ] 主体是否按信息重要性排序
- [ ] 数据和引用是否准确并有来源
- [ ] 企业简介是否符合事实
- [ ] 是否有联系方式方便媒体跟进
- [ ] 是否避免了广告化语言
- [ ] 事实是否经过核实
- [ ] 是否准备了多媒体素材
- [ ] 是否有后续传播计划

## WF-003：高管致辞工作流

### 4.1 适用场景

本工作流适用于以下高管发言情境：

- 重大庆典活动致辞（周年庆典、上市庆典、颁奖典礼）
- 重要会议开幕致辞（行业峰会、战略发布会、客户大会）
- 年度会议主旨演讲（年会、董事会、投资者大会）
- 公开信撰写（致员工信、致客户信、致股东信）
- 媒体专访开场白和总结陈词
- 新年致辞和节日祝福
- 危机时刻的高管声明
- 产品或战略发布总结陈词

### 4.2 高管致辞类型

| 类型 | 时长建议 | 风格特点 | 核心要素 |
|-----|---------|---------|---------|
| 庆典致辞 | 5-10分钟 | 热情、感恩、展望 | 回顾、感谢、愿景 |
| 主题演讲 | 20-40分钟 | 专业、深度、启发 | 洞察、分析、建议 |
| 公开信 | 不限 | 真诚、具体、情感 | 背景、态度、行动 |
| 年会致辞 | 10-15分钟 | 激励、团结、方向 | 总结、表彰、展望 |

### 4.3 工作流程

#### 步骤一：场景分析（15分钟）

**分析维度**：

```
场合分析 → 听众画像 → 场合调性 → 发布预期
```

**场合关键信息**：
- 活动名称和主题
- 举办时间、地点、规模
- 参与人员构成
- 活动背景和目的
- 前序环节安排
- 后续环节安排

**听众画像**：
| 听众类型 | 关注点 | 期待内容 |
|---------|--------|---------|
| 内部员工 | 发展方向、个人机会 | 激励、认可、愿景 |
| 客户伙伴 | 合作价值、服务能力 | 承诺、价值、展望 |
| 投资者 | 盈利能力、增长潜力 | 战略、回报、风险 |
| 媒体 | 新闻价值、独家信息 | 观点、亮点、新动态 |
| 政府嘉宾 | 社会责任、发展贡献 | 合规、贡献、地方发展 |

#### 步骤二：高管风格把握（15分钟）

**风格评估维度**：

```
语言风格 → 思维方式 → 领导特质 → 情感表达
```

**常见高管风格类型**：

| 风格类型 | 特点 | 适合场景 | 注意事项 |
|---------|------|---------|---------|
| 战略型 | 高屋建瓴、前瞻性强 | 战略发布、投资者沟通 | 避免空洞 |
| 亲和型 | 温暖真诚、平易近人 | 员工活动、客户活动 | 避免随意 |
| 专业型 | 逻辑严谨、数据说话 | 技术发布、行业峰会 | 避免枯燥 |
| 激情型 | 富有感召、激励人心 | 年会、表彰活动 | 避免夸张 |
| 稳健型 | 务实沉稳、可靠可信 | 危机声明、官方发言 | 避免情绪化 |

**风格匹配检查**：
```
目标风格 ←→ 场合要求 ←→ 听众期待 ←→ 个人特质
```

#### 步骤三：核心信息设计（20分钟）

**信息层次结构**：

**必讲信息（不能遗漏）**：
```
1. 对场合的回应和感谢
2. 对听众的问候和尊重
3. 核心主题和关键观点
4. 对未来的展望和承诺
5. 感谢和祝福
```

**可选信息（根据场合调整）**：
- 行业洞察和趋势判断
- 企业发展历程和成就
- 团队努力和贡献表彰
- 战略规划和发展方向
- 社会责任和价值追求

**信息优先级排序**：
```
P0（必须讲）：
P1（重要讲）：
P2（有时间讲）：
P3（可省略）：
```

#### 步骤四：致辞结构设计（20分钟）

**致辞经典结构**：

**结构一：回顾-感谢-展望（三段式）**
```
【开场】问候 + 场合回应（1-2分钟）
【回顾】感恩过去 + 成绩总结（2-3分钟）
【感谢】感谢贡献者 + 具体致谢（2-3分钟）
【展望】未来愿景 + 行动号召（2-3分钟）
【结语】祝福 + 号召（0.5-1分钟）
```

**结构二：洞察-分析-建议（三段式）**
```
【开场】主题引入 + 重要性说明（2-3分钟）
【洞察】行业分析 + 趋势判断（8-10分钟）
【建议】行动建议 + 方向指引（8-10分钟）
【结语】总结 + 号召（1-2分钟）
```

**结构三：问题-回应-行动（三段式）**
```
【开场】提出问题 + 回应关切（3-5分钟）
【回应】分析原因 + 解决思路（10-15分钟）
【行动】具体措施 + 承诺保证（5-8分钟）
【结语】展望未来 + 感谢（1-2分钟）
```

**开场设计**：
```
开场方式选择：
├── 问候式开场：直接问候，简单明了
├── 场景式开场：描述现场，建立连接
├── 故事式开场：用故事引出主题
├── 数据式开场：用数据吸引注意
├── 引用式开场：用名言或故事开场
└── 互动式开场：提问或号召参与
```

**高潮设计**：
- 最核心的观点放在致辞前三分之一
- 设置1-2个情感高潮点
- 用具体的故事或案例支撑观点
- 适当重复关键信息加深印象

**结语设计**：
```
结语要素：
├── 总结要点（简明扼要）
├── 情感升华（引发共鸣）
├── 行动号召（指向未来）
└── 祝福感谢（礼貌收尾）
```

#### 步骤五：初稿撰写（60分钟）

**撰写原则**：
```
✓ 使用高管第一人称
✓ 体现个人风格和领导魅力
✓ 语言精炼但有感染力
✓ 适当使用修辞增强表达
✓ 穿插具体数据和案例
✓ 平衡理性和感性表达
✗ 避免过于书面化的表达
✗ 避免空洞的口号和套话
✗ 避免攻击或贬低他人
✗ 避免过度承诺
```

**语言风格调校**：
- 正式程度：根据场合调整正式程度
- 情感强度：庆典热烈、危机冷静
- 专业程度：内部活动可以轻松，投资者场合需要严谨
- 本地化：根据听众调整方言或本地化表达

**引用语设计**：
```
引用语类型：
├── 自身经历：增加真实感和亲和力
├── 团队故事：展现团队精神和集体成就
├── 客户案例：增强说服力和客户价值
├── 名人名言：增加权威性和说服力
└── 数据支撑：用数据增强可信度
```

#### 步骤六：口语化调校（20分钟）

**朗读测试**：
```
测试要点：
├── 是否顺口易读
├── 是否适合演讲节奏
├── 是否有难发音的词
├── 是否有不自然的停顿
└── 是否有需要强调的地方
```

**演讲优化**：
- 将长句拆分为短句
- 添加过渡语帮助演讲
- 标注停顿和强调位置
- 准备关键词提示而非逐字稿

#### 步骤七：配套材料准备（15分钟）

**配套物料清单**：

| 物料类型 | 内容要求 | 用途 |
|---------|---------|------|

| 交付物 | 用途 | 要求 |

## WF-004：企业声明工作流

### 5.1 适用场景

本工作流适用于以下企业声明情境：

- 官方立场声明（行业政策表态、重大事件回应）
- 情况说明（澄清误解、说明事实）
- 权益声明（知识产权维权、商业诋毁反击）
- 合作声明（合作关系公布、终止合作公告）
- 人事声明（重要人事变动说明）
- 安全声明（产品安全、食品安全、信息安全）
- 环境声明（环保承诺、碳中和目标）
- 社会责任声明（公益投入、ESG承诺）

### 5.2 声明类型分析

| 类型 | 权威性要求 | 情感倾向 | 详细程度 | 典型篇幅 |
|-----|----------|---------|---------|---------|
| 官方声明 | 最高 | 中立客观 | 详尽 | 500-1000字 |
| 情况说明 | 高 | 客观陈述 | 中等 | 300-600字 |
| 澄清声明 | 高 | 坚定但理性 | 详尽 | 400-800字 |
| 权益声明 | 高 | 坚定 | 中等 | 300-500字 |
| 承诺声明 | 中高 | 诚恳 | 中等 | 200-400字 |

### 5.3 工作流程

#### 步骤一：声明目的确认（10分钟）

**核心问题梳理**：

```
Q1: 发布声明的直接目的是什么？
   ├── 说明情况 → 事实澄清
   ├── 表明立场 → 态度表态
   ├── 纠正错误 → 维权反击
   ├── 回应关切 → 解答疑问
   └── 承诺行动 → 表态改进

Q2: 声明希望影响哪些受众？
   ├── 媒体和公众 → 需要通俗易懂
   ├── 监管机构 → 需要合规严谨
   ├── 投资者 → 需要准确完整
   ├── 合作伙伴 → 需要清晰明确
   └── 内部员工 → 需要统一口径

Q3: 期望达到什么效果？
   ├── 信息传递 → 让受众知道发生了什么
   ├── 认知改变 → 让受众改变看法
   ├── 行为引导 → 让受众采取行动
   └── 关系维护 → 维护与受众的关系
```

#### 步骤二：法律和合规审查（15分钟）

**法律风险评估**：

```
审查要点：
├── 是否可能构成自认或不利证据
├── 是否有泄露商业秘密的风险
├── 是否有侵犯他人权益的风险
├── 承诺是否具有法律约束力
├── 是否符合监管披露要求
└── 是否可能引发诉讼风险
```

**合规要求清单**：
- 上市公司信息披露要求
- 行业监管特殊规定
- 广告法和反不正当竞争法
- 个人信息保护相关要求
- 知识产权相关法律规定

#### 步骤三：内容框架设计（20分钟）

**声明标准结构**：

```
【声明标题】简明扼要，一目了然
【声明编号】便于追踪管理
【声明正文】
  ├── 背景说明（可选）
  ├── 事实陈述
  ├── 立场表明
  ├── 原因解释（可选）
  ├── 措施承诺
  └── 联系方式
【声明落款】企业名称和日期
【附件】补充材料（可选）
```

**立场表达原则**：

| 立场类型 | 适用场景 | 表达方式 |
|---------|---------|---------|
| 支持认同 | 政策支持、合作表态 | 积极、明确 |
| 反对质疑 | 竞品攻击、错误言论 | 坚定、有据 |
| 中立观望 | 情况不明、复杂事件 | 审慎、保留 |
| 澄清说明 | 误解澄清、事实纠正 | 客观、有据 |
| 道歉认错 | 确实存在过错 | 诚恳、负责 |

#### 步骤四：初稿撰写（40分钟）

**撰写要点**：

```
✅ 标题规范：
   • 企业名称 + 声明主题
   • 如："XX公司关于XXX事件的声明"
   • 避免标题党或过度情绪化

✅ 正文撰写：
   • 语言正式、表述准确
   • 事实陈述与观点表达分开
   • 逻辑清晰、层次分明
   • 用词严谨、避免歧义

✅ 立场表达：
   • 明确清晰、不模糊
   • 有理有据、不武断
   • 适度温和、避免攻击性
   • 承诺具体、可验证

✅ 结尾处理：
   • 提供官方联系方式
   • 表示愿意进一步沟通
   • 保留进一步行动的权利（必要时）
```

**禁止事项**：
```
❌ 未经核实的事实陈述
❌ 可能侵犯他人权益的内容
❌ 过度情绪化或攻击性的语言
❌ 无法兑现的承诺
❌ 泄露商业秘密或敏感信息
❌ 与其他公开声明矛盾的内容
```

#### 步骤五：内部审批流程（15分钟）

**审批层级建议**：

| 声明类型 | 审批层级 | 审批时间 |
|---------|---------|---------|
| 常规声明 | 公关部门负责人 | 1-2小时 |
| 重要声明 | 公关+法务+业务负责人 | 4-8小时 |
| 高管声明 | 公关+法务+高管层 | 8-24小时 |
| 紧急声明 | 高管授权+法务 | 1-4小时 |

**审批检查清单**：
- [ ] 事实核实完成
- [ ] 法律风险评估通过
- [ ] 数据准确无误
- [ ] 立场表达恰当
- [ ] 承诺可以兑现
- [ ] 格式规范统一
- [ ] 相关部门确认

#### 步骤六：多渠道适配（10分钟）

**渠道版本准备**：

| 渠道 | 版本调整 | 字数 | 重点 |
|-----|---------|------|-----|
| 官网 | 完整版 | 500-1000字 | 详尽、全面 |
| 官方微博 | 简短版 | 200-300字 | 核心观点 |
| 官方微信 | 中等版 | 300-500字 | 适合阅读 |
| 媒体邮件 | 附背景资料版 | 正文+附件 | 便于引用 |
| 新闻网站 | SEO优化版 | 500-800字 | 关键词优化 |

### 5.4 输出物清单

| 交付物 | 用途 | 要求 |
|-------|------|------|
| 正式声明 | 官网发布存档 | PDF+Word |
| 短版本 | 社交媒体 | 核心要点 |
| 媒体问答 | 媒体应对 | Q&A清单 |
| 内部口径 | 员工口径统一 | 要点列表 |
| 发布说明 | 执行指导 | 渠道+时机 |

### 5.5 质量检查表

- [ ] 声明目的是否清晰明确
- [ ] 事实陈述是否经过核实
- [ ] 立场表达是否恰当
- [ ] 法律风险是否已评估
- [ ] 承诺是否能够兑现
- [ ] 格式是否符合规范
- [ ] 是否经过必要审批

- [ ] 多渠道版本是否准备

|---------|---------|-----|
| 平淡无奇 | 加入数据或亮点 | "企业发布新产品" → "XX产品发布：性能提升50%，价格降低30%" |
| 过于笼统 | 具体化呈现 | "公司取得好成绩" → "XX公司Q3营收突破10亿，同比增长40%" |
| 缺乏吸引力 | 制造悬念或反差 | "产品降价通知" → "最高降价50%：XX品牌全线产品调价" |
| 信息冗余 | 删除冗余，保留核心 | 精炼标题，去除废话 |

**开头优化技巧**：

| 问题类型 | 优化技巧 | 示例 |
|---------|---------|-----|
| 开门见山不够 | 重构导语，优先呈现核心 | 先说结果，再说背景 |
| 过于冗长 | 压缩到核心信息 | 删除铺垫，直奔主题 |
| 缺乏吸引力 | 加入亮点或悬念 | 吸引读者继续阅读 |
| 与标题重复 | 差异化表述 | 提供标题未包含的信息 |

**正文优化技巧**：

| 优化维度 | 操作方法 |
|---------|---------|
| 逻辑优化 | 重排段落顺序、添加过渡句、增强因果关联 |
| 表述优化 | 改写拗口表达、精简冗余内容、统一术语 |
| 说服力优化 | 增加数据支撑、添加案例佐证、补充引用 |
| 可读性优化 | 使用小标题、分段、加粗关键信息 |

**结尾优化技巧**：

| 问题类型 | 优化方法 |
|---------|---------|
| 虎头蛇尾 | 补充总结和行动号召 |
| 过于突兀 | 添加过渡，呼应开头 |
| 空洞口号 | 具体化承诺，增加实质内容 |
| 信息残缺 | 补充联系方式、相关链接等必要信息 |
