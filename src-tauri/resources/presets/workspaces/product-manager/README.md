# 产品经理工作空间使用指南

## 空间概述

这是一个为产品经理设计的完整工作空间，提供了开展产品管理工作所需的全部文档模板和参考资源。空间包含身份定义、工作哲学、工作流程、工具资源等多个模块，涵盖了产品经理工作的各个维度。

本空间旨在帮助产品经理系统化地开展日常工作，提供标准化的文档模板和经过验证的方法论参考。无论你是经验丰富的产品经理还是刚入行的新人，这个空间都能为你的工作提供有价值的支持。

## 空间结构

### 核心文档

**IDENTITY.md** - 产品经理身份定义

这份文档定义了产品经理的核心角色定位、专业能力要求和价值观准则。它帮助产品经理建立清晰的职业认知，明确自己的职责边界和专业发展方向。这是一切产品管理工作的基础性文档。

**SOUL.md** - 工作哲学

这份文档阐述了产品经理的核心理念和思维方式，包括本质认知、决策框架、沟通原则等。它指导产品经理在面对复杂问题时如何思考和决策，是建立专业思维方式的参考框架。

**AGENTS.md** - 工作流程

这份文档定义了五个核心工作流程：产品战略规划、产品需求分析、产品设计与验证、产品迭代管理、产品运营分析。每个流程都有明确的目标、步骤和产出物，是开展日常工作的操作指南。

**USER.md** - 目标用户

这份文档阐明了产品经理服务的各类用户群体及其需求特征，包括内部利益相关者和外部最终用户。它是开展用户研究和产品设计的参考依据。

**TOOLS.md** - 工具资源

这份文档系统梳理了产品经理工作中常用的工具资源，按照功能类别进行组织。它帮助产品经理建立完整的工具能力体系，提升工作效率。

**HEARTBEAT.md** - 系统状态

这份文档记录了产品经理工作空间的运行状态和健康指标。它提供了对空间维护状态的监控视图，帮助识别需要关注的问题和改进机会。

## 使用方法

### 新建产品需求文档

当你需要编写产品需求文档时，首先阅读 **template-prd.md** 模板，了解PRD的标准格式和内容要求。然后基于模板创建新的PRD文档，填写具体的产品需求内容。

在编写PRD时，确保包含以下核心部分：需求背景、用户故事、功能描述、业务规则、验收标准等。参考示例文档中的优秀实践，确保文档的完整性和专业性。

### 规划产品路线图

当你需要规划产品的发展路线时，首先阅读 **template-roadmap.md** 模板，了解路线图规划的基本框架。然后基于模板创建新的路线图文档，结合战略规划流程和实际业务情况填充内容。

产品路线图应该体现产品的发展愿景、阶段性目标和关键里程碑。确保路线图与公司战略保持一致，并定期根据市场变化进行更新。

### 参考实际案例

当你需要参考类似产品的最佳实践时，可以查阅 **docs/examples/** 目录下的案例文档。这些案例展示了不同类型产品的规划方法和工作流程，可以为你的工作提供借鉴和启发。

### 维护系统状态

定期查看 **HEARTBEAT.md** 文件，了解产品经理工作空间的运行状态。如果发现问题或有改进建议，及时进行更新和完善。

## 工作流程应用

### 战略规划流程应用

在执行战略规划工作时，按照 **AGENTS.md** 中定义的流程步骤进行：

1. 进行战略环境分析，包括市场分析、竞争分析、技术趋势分析等
2. 开展用户洞察研究，构建用户画像和用户旅程
3. 设定战略目标，使用SMART原则确保目标清晰可衡量
4. 设计战略路径，明确市场定位和竞争策略
5. 编写战略文档，与利益相关者沟通并获得认可

### 需求分析流程应用

在执行需求分析工作时，按照流程步骤进行：

1. 系统性地收集需求，建立需求池
2. 整理和分类需求，识别需求之间的关联
3. 深入分析和验证核心需求，确保需求的真实性和价值
4. 使用优先级框架进行需求排序
5. 编写规范的需求文档，确保团队对需求达成共识

### 产品设计流程应用

在执行产品设计工作时，按照流程步骤进行：

1. 设计产品的信息架构
2. 设计功能流程和交互逻辑
3. 制作原型并进行内部评审
4. 进行用户验证测试
5. 整理设计文档，与开发团队进行交接

### 迭代管理流程应用

在执行迭代管理工作时，按照流程步骤进行：

1. 参与迭代计划会议，确定迭代目标和范围
2. 在迭代过程中持续进行需求澄清
3. 跟踪开发进度，监控风险
4. 进行产品体验把关，确保交付质量
5. 组织迭代复盘，总结经验教训

### 运营分析流程应用

在执行运营分析工作时，按照流程步骤进行：

1. 建立产品指标体系
2. 确保数据的持续采集和监控
3. 进行深度数据分析，挖掘洞察
4. 识别产品问题和改进机会
5. 制定和执行运营策略
6. 评估策略效果，持续迭代优化

## 常见问题

**如何选择合适的优先级框架？**

常用的优先级框架包括ICE评分、RICE评分、MoSCoW方法等。ICE适合快速评估，RICE适合资源分配场景，MoSCoW适合大型项目分解。具体选择应根据任务特点、团队习惯和决策场景来决定。

**如何平衡多个利益相关者的需求？**

利益相关者之间出现需求冲突是常见的。我会深入理解各方诉求的底层原因，寻找共同点和更深层的共同目标。对于无法调和的分歧，我会以用户价值和商业价值为导向做出决策，并清晰解释决策逻辑。

**如何处理模糊或不完整的需求？**

模糊的需求需要主动澄清和验证。我会与需求提出者深入沟通，追问需求的背景和预期结果。必要时，我会进行用户调研或数据分析，获取更多信息后再做判断。
