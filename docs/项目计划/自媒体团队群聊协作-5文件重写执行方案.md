## 关键设计决策说明

### 为什么子 Agent 用"尾部追加"而不是"重写"？

1. **低风险**：不破坏已有的核心职责定义（热搜抓取、文案创作、视觉设计）和平台风格知识
2. **最小改动**：只追加一段群聊协作规范，不触碰任何现有内容
3. **清晰隔离**：群聊规范作为独立段落，便于后续维护和调整

### 为什么总监用"局部重写"而不是"追加"？

1. **删除旧规范**：总监的 SOUL.md 和 AGENTS.md 中大量内容是 sessions_send 专属的（timeoutSeconds 配置、sessionKey 格式、委派消息格式等），如果保留会造成 Agent 行为混乱
2. **避免冲突**：旧规范和新规范如果共存，Agent 可能"时而在群里 @，时而用 sessions_send"，行为不可预测
3. **干净利落**：删除 → 替换，不留歧义

### 为什么不在子 Agent 中保留 sessions_send 工具权限？

- `openclaw.json` 中子 Agent 的 `tools.alsoAllow` 中不包含 `sessions_send`（只有 media-director 有 `sessions_send` 和 `sessions_list`），所以子 Agent 从技术上就无法使用 sessions_send
- 但为了防止 Agent 误用 message 等后台工具，我们在群聊规范中明确禁止

### 保留的核心价值

| 文件 | 保留的内容 | 原因 |
|------|-----------|------|
| media-director SOUL.md | 理解需求、任务拆解、结果整合、团队成员、典型场景 | 质量极高，直接复用 |
| media-director AGENTS.md | 会话启动、流程一（理解需求）、流程二（任务拆解） | 质量极高，直接复用 |
| hotsearch-monitor SOUL.md | 全部核心内容（热搜抓取、选题生成、归档、筛选策略） | 专业且完整 |
